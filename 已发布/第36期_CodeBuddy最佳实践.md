# 第36期 | 我把"Markdown 一键打印"做成了开源扩展，全程只用 CodeBuddy

> 大家好，我是小智。前几期聊了不少 AI 行业的宏观话题，今天来点动手的——说说我这周真刀真枪做完的一件小事：
> 把「在CodeBuddy编辑器里一键把 Markdown / 代码文件打印成排版好的 HTML、还能另存成 PDF」这个需求，丢给了 CodeBuddy，
> 从写第一行代码到打包、测试、修 Bug、开源发布，全程 AI 协作。
> 产物已经开源在 GitHub，地址文末给到。它到底好不好用、CodeBuddy 协作顺不顺手，你看完这篇心里就有数了。

📌 本文看点：
- 一句话需求，CodeBuddy 一天交付第一个能跑的版本
- 翻车现场：一个"自作聪明"的兜底逻辑，差点让我打错文件
- 从本地到开源：README、截图、License、Release 一个不少

## 一、起因：一个"就差一个插件"的小需求

写 Markdown 久了会有个很实在的痛点：文档写好了，想打印成纸质版或归档成 PDF，编辑器里却总差一个"顺手的打印键"。

编辑器自带的打印要么调浏览器页面，要么样式难看。VSCode / CodeBuddy 生态里能用的打印扩展少得可怜，还大多依赖网络服务。

我自己天天泡在 AI 工具里，这个需求又不复杂，那就干脆自己造一个——**让 CodeBuddy 来造。**

## 二、开工：把需求"翻译"成 AI 能执行的任务

给 CodeBuddy 的第一个指令，我没有让它"写个扩展"，而是给了它三个明确的约束：

- **目标平台**：VS Code / CodeBuddy 扩展，零第三方依赖，装上就能用；
- **核心能力**：Markdown 按排版渲染（标题、表格、代码块都要好看），其他文本文件按等宽字体原样打印；
- **交付标准**：能打包成 `.vsix` 安装包，支持右键菜单、状态栏、快捷键多个入口。

只讲需求、不预设实现。CodeBuddy 自己把工程拆成了两部分：渲染核心放 `lib/`（负责把 Markdown 变成排版 HTML），扩展侧做入口和宿主适配（右键、预览按钮、命令面板）。

当天第一个能跑的版本就出来了。

> 小技巧：AI 不缺写代码的能力，缺的是「你想要的到底是什么」的边界。目标、约束、验收标准说清楚，它就能自己飞。

## 三、最有价值的一课：AI 也会"自作聪明"

上线后陆续修了几个环境兼容问题，直到 1.5.1 版本，我让它解决一个 Bug：

> 场景：某个 Markdown 文件第一次以预览模式打开时，在预览窗口里右键打印，提示"没有可打印的文件"——因为预览窗口拿到焦点后，编辑器认为"当前没有活动文件"。

CodeBuddy 给出的方案是：**缓存"上一次打开的文件"，拿不到当前文件时就用缓存兜底。**

这个方案看起来无懈可击，实则埋了个雷：当用户新打开文档 B 去打印时，一旦上下文解析失败，就会**把上一份文档 A 打印出来**——打印错文件，比打印不出来更可怕。

用户反馈后我们复盘，结论很清晰：

> 「凡是 AI 拿不准的，宁可停下来让用户确认，也不要自作主张去猜。」

1.5.2 版本改成按"当前上下文"逐级精确定位：当前光标所在文件 → 当前激活的标签页 → 预览窗口的标题反查源文件……实在同时匹配多个候选，就**弹出列表让用户点选**。绝不回溯使用"历史文件"。

这一课不仅适用这个插件，也适用所有人和 AI 的协作场景。

## 四、我用 CodeBuddy 的五条最佳实践

这一个项目跑下来，我把心得收敛成五条，分享给想上手的朋友：

1. **让它先读代码再动手。** AI 有上下文才不瞎改。每次让它改东西前，先确认它真的"看"过相关文件，而不是凭记忆硬写。

2. **拆成"能做 → 能装 → 能测"的小循环。** 先出最小可用版本，本地打包 `.vsix` 装上真机测试，再谈新功能。每个循环都短、都可回滚。

3. **出问题就贴"报错原文 + 截图"，别转述。** 预览窗口拿不到焦点、右键菜单被宿主拦截……这类环境兼容问题，只有原始报错和界面截图能让 AI 精准定位，转述会失真。

4. **凡是涉及"猜"的逻辑，明说"拿不准就问"。** 给 AI 的兜底策略定基调：宁可多弹一次确认框，也不要在打印、删除、覆盖这类动作上自作主张。

5. **发布类琐事全部交给它。** 提交信息怎么写、tag 怎么打、Release 怎么发、README 配图怎么放，这种有章可循的重复劳动，AI 做起来又快又稳，还能顺手把 `.gitignore` 给你理干净。

## 五、开源出去：小工具也要有完整的交付

代码写出来只是第一步。开源一个项目，其实是一整套交付物：

- **公开仓库**：代码 + MIT 协议，任何人都能看、能改、能商用；
- **README**：一句话说清它解决什么问题、怎么安装、有哪些入口，配真实使用截图；
- **CHANGELOG**：版本演进和修复记录，用户能看懂你的迭代；
- **Release 安装包**：把打包好的 `.vsix` 挂在 GitHub Release 上，用户下载即装；
- **工程卫生**：临时文件、打包产物写进 `.gitignore`，仓库保持干净。

这些琐碎但有章法的事，CodeBuddy 基本一条龙搞定。项目已经在 GitHub 开源：

**📦 仓库地址：https://github.com/haierzld/print-md**

（支持 Markdown 与几十种代码/文本文件的打印，零依赖、免费、MIT 协议。有需要的朋友可以直接下载试用，觉得好用欢迎点个 Star，遇到问题可以在仓库提 Issue。）

## 六、小智说两句

工具很小，但"人类定目标与边界、AI 干执行与细节"这条路，我算是完整走通了一遍。

如果你也想让 CodeBuddy 帮你做点什么，别从大项目开始——先选一个你天天都在用、又总觉得"差点意思"的小功能，把它做到能装、能用、敢开源。

> 一句话总结：AI 写代码的下限很高，上限取决于你给它的上下文和边界——把需求讲清楚、把兜底策略定好，剩下的大胆交给它。
