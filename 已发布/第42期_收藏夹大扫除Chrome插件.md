## 一、起因：收藏夹，怎么就成了"数字杂物间"

写公众号这几年，我最常用的"资料库"就是浏览器收藏夹。看到好文章、好工具，第一反应就是"先收藏，回头细看"。

结果呢？**"回头"永远没来，"收藏"倒是越来越多。**

那天我随手点开收藏夹管理页，吓了一跳：600 多条。里面大致是三堆东西——

- 同一个链接存了三四遍，标题还各不相同（每次看到又顺手收藏一次）；
- 一堆显示"无法访问"的失效链接，多半是文章被删、站点关闭；
- 还有一批"以后一定看"的，最后一次点开时间是三年前。

收藏夹本来的意义，是"帮我把好东西存住"；结果它自己变成了一个"清理成本比收益还高"的杂物间。**想删，舍不得；想留，又用不上。**

这种感觉，估计你也有。

## 二、开工：把"我想要"翻译成四条硬需求

这次我没有跟 CodeBuddy 说"给我写个插件"，而是照旧先把"边界"钉死，一共四句话：

1. **它是什么。** 一个 Chrome 浏览器扩展，用 Manifest V3 新标准，零第三方依赖，所有数据只在本地处理、绝不上传。
2. **它能干什么。** 读取我的收藏夹，自动找出两类"垃圾"：重复的（同一个网址存了多次）和失效的（点了打不开的）；支持勾选后批量清理。
3. **它怎么跟我交互。** 点一下浏览器右上角的插件图标，弹出一个小面板，上面三个标签页——重复项、失效链接、全部收藏；每条前面一个勾选框，底部一个"导出备份"、一个"清理选中"。
4. **怎么算做完。** 能通过"加载已解压的扩展程序"在我自己的浏览器里跑起来；代码整理干净，配一份 README，开源到 GitHub。

把"是什么、干什么、怎么用、怎么算完"讲清楚之后，剩下的我基本没操心。

半天不到，第一个能跑的版本就出来了：图标、弹窗、扫描逻辑、清理按钮，一应俱全。

> 这里插一句系列老话：**AI 不缺写代码的能力，缺的是"你想要的到底是什么"。** 目标、约束、验收标准说清楚，它就能自己飞起来。

## 三、踩坑现场：AI 也会"想当然"

AI 写代码很快，但也特别容易"想当然"。这个项目里它翻了两次车，而且都挺有代表性。

**翻车一：为了省事，申请了"通天的权限"。**

第一个版本能跑通，但我打开扩展详情页一看，眉头就皱了——它申请了 `&lt;all_urls&gt;`（读取所有网站数据）的权限。

我明明只是要整理收藏夹、偶尔点一下链接看看活没活着，凭什么要看我所有网页？

CodeBuddy 的初衷是"省事"：要检测失效链接，就得能访问这些网址，那干脆一步到位申请全站权限。但站在用户立场，这就是典型的**"能力越大、越像流氓软件"**——一个整理收藏夹的小工具张口就要"看所有网站"，谁敢装？

后来我让它按"最小必要"原则改：只申请 `bookmarks`（收藏夹）权限；检测链接时，才在用户主动点击的那一刻发起请求，并在界面上写明白"只用于检查链接是否可访问，不会上传任何数据"。**权限这东西，能少要一分，就多一分信任。**

**翻车二：删得太"勇猛"，一按就没了。**

清理功能的第一版是这么写的：勾选 → 点"清理" → 直接删。干脆利落。

我拿测试账号试了一下，一键清掉一百多条，屏幕上干干净净——然后我愣住了：**万一删错了呢？能撤回吗？**

答案是不能。`chrome.bookmarks.remove` 执行完就是执行完，没有回收站。

我赶紧让它加了三道保险：第一，点清理前，自动把当前收藏夹导出成一份备份文件下载下来；第二，弹一个确认框，默认按钮从"确定"改成"取消"；第三，清理只删勾选的那几条，绝不"顺手"多删。

> 这也逼我总结出第二条老规矩：**凡是"删、改、覆盖"这种不可逆的动作，宁可多停一步让用户确认，也绝不自作主张。** 这一条，正好接上第 36 期那个"打错文件"的教训。

**顺带一个惊喜：AI 主动提醒了我一件事。**

我原本的想法很简单：只要能打开，就不算失效。CodeBuddy 实现时加了一句提示——很多网站有"防盗链"、需要登录才能访问，机器去请求会被拒，但人点开其实是好的。

所以它没有一刀切，而是把结果分成了两档：**明确连不上的（超时、域名没了、404）标成"失效"；拿不准的标成"存疑"**，让我自己点开看看。

这个处理挺打动我——**它没有假装自己什么都懂，而是把判断权交还给了人。**

## 四、成品长什么样：三个按钮，治好收藏夹

跑了几轮之后，这个插件稳定成了我想要的样子。功能不花哨，但每一下都打在痛点上：

- **扫重复：** 按网址去重，同一个链接存了几遍一目了然，留一条、删其余；
- **扫失效：** 一键并发检测，死链、打不开的单独列一列；
- **一键备份：** 动手之前先把收藏夹导出成文件，删错了也能找回来；
- **批量清理：** 勾选、确认、删除，一条龙。

它的"骨架"其实很简单，一个 `manifest.json` 就说明了全部诉求：

```json
{
  "manifest_version": 3,
  "name": "收藏夹大扫除",
  "version": "1.0.0",
  "permissions": ["bookmarks"],
  "action": { "default_popup": "popup.html" }
}
```

注意那份 `permissions` 清单——只有一个 `bookmarks`。这就是上面那场"权限翻车"之后，最终收敛下来的结果。

名字我起得很直白，就叫**"收藏夹大扫除"**。看着简单，但它解决的是我拖了好几年的一个具体麻烦。

## 五、让别人也能用上：从本地加载到开源上架

插件在自己电脑上跑通，只是第一步。想分享给别人，还有一条"交付路径"要走。整个过程，我照样交给 CodeBuddy 一条龙：

1. **本地装起来。** 打开浏览器的扩展管理页（`chrome://extensions`），打开右上角的"开发者模式"，点"加载已解压的扩展程序"，选中项目文件夹——插件立刻出现在工具栏上。
2. **打包。** 用同样的入口把文件夹打成 `.zip` 安装包，方便发给朋友，也方便作为上架的提交物。
3. **开源。** 把代码托管到 GitHub，配一份说人话的 README：这插件解决什么问题、怎么安装、怎么用、需要哪些权限、为什么需要（这一条尤其重要，用户最怕黑箱）。
4. **上架商店（可选）。** 如果想进 Chrome 应用商店，需要注册开发者账号（一次性 5 美元）、填写隐私说明（讲清楚数据怎么用、绝不上传）、提交审核，一般几天出结果。

**📦 仓库地址：https://github.com/haierzld/bookmark-cleaner**

（顺着第 36 期的老规矩开源，MIT 协议，免费。有需要的朋友可以直接下载试用，觉得好用来个 Star，遇到问题在仓库提 Issue。）

## 六、小智说两句

这是我用 CodeBuddy 做完的第三个"真产品"。三次下来，我的感受越来越一致：

**真正难的，从来不是写代码，而是想清楚"要什么"和"不要什么"。**

这次的"不要什么"，就是那两个翻车点——不要贪心的权限，不要无法挽回的删除。把这两条想清楚，剩下的代码，AI 几乎没让我操心。

如果你也想让 CodeBuddy 帮你做个插件，别一上来就挑大工程。就从你每天在用、又总觉得"差点意思"的小地方下手：一个总也理不清的收藏夹、一步重复劳动、一句心里的"要是有个工具就好了"。

> 一句话总结：AI 能把你从"敲代码"里解放出来，但"这个工具该怎么长、边界在哪、底线是什么"，永远得由你这个"产品经理"说了算。

下期周三见，我们聊个技术词：**RAG——为什么 AI 能"读着你的文档"回答问题，还不瞎编。**
