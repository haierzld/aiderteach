DevDay 之后，后台问得最多的一个问题是：OpenAI 的 dots，跟我们天天在用的豆包、CodeBuddy、WorkBuddy，到底有什么区别？是不是又一个聊天机器人换皮？

今天用我们第 7 期讲过的那张“七层关系”图，把它们摆到同一把尺子上量一遍。

四个AI摆在一起

01

WHO

一、先把四个东西摆清楚

dots（OpenAI）：24 小时在线的常驻个人智能体。每个 dot 自带云电脑、浏览器和执行环境，能操作 4000 多个应用，你不在时它继续干活，还能主动找活。有 Custom Rules、权限控制和自动操作审查；企业版有 Specialist dots，按岗位配置身份和权限。

豆包（字节）：面向大众的 AI 助手，覆盖手机、网页与硬件，强在内容理解、中文语境和日常陪伴；在工作场景里也出现了“伙伴”式的角色设计（不同岗位/身份的角色）。这里说的都是公开可见的形态，具体功能以官方说明为准。

CodeBuddy：面向开发者的编码智能体。活在 IDE 和代码仓库里，读工程、改代码、跑命令、跑测试，产出是可运行的代码与改动。

WorkBuddy：面向日常办公任务的助手型智能体，处理文档、表格、信息整理、流程这类“办公室里的活”。

一句话区分：dots 是“常驻同事”，豆包是“随身助理”，CodeBuddy 是“工程搭档”，WorkBuddy 是“办公室帮手”。


02

RULE

二、七层这把尺子

第 7 期我们把 AI 拆成了七层，从下往上：

1

Token → 2. 提示词 → 3. 上下文 → 4. Agent → 5. Harness → 6. MCP → 7. Skills

现在逐层看，各家在哪用力。

第 1 层 Token：已经不是战场

这一层的竞争基本结束了。价格被打到地板，缓存再减半，没人能靠“更便宜的字”赢。它变成了所有人的水电煤。

第 2 层 提示词：正在被“产品化”

有意思的变化在这儿：提示词正在从“你要会写”变成“产品替你写好”。

 

dots 把它做成 Custom Rules（你定规则，它长期遵守）

 

豆包把它做成 角色/伙伴模板（你选一个身份，话术和边界跟着来）

 

CodeBuddy 把它做成 规则文件与命令（写在工程里，团队共用）

方向一致：把“会不会问”这件事，从用户身上拿走。

第 3 层 上下文：拼的是“它有多了解你”

 

dots 靠长期在岗积累，加上 4000 多个应用里的历史数据

 

豆包靠账号与内容生态，中文语境、热点理解是它的主场

 

CodeBuddy 靠整个代码仓库与工程历史

 

WorkBuddy 靠你的文档、表格与流程

这一层决定了“它懂不懂你的事”，也是各家最难被复制的部分。

第 4 层 Agent：四家都在，但“在岗时间”不同

这是 dots 这次真正往前推的一层：从“你叫它才动”，到 7×24 在岗、还会主动找活。

豆包、CodeBuddy、WorkBuddy 目前更偏“你发起—它完成”；dots 把“常驻”做成了默认状态。常驻这件事，把后面几层的要求整个抬高了。

第 5 层 Harness：差别最大的一层

一个 7×24 在岗、握着账号和权限的东西，靠什么不出事？

 

dots：Custom Rules + 权限控制 + 自动操作审查，企业侧还有 Specialist dots 的身份与凭证管理

 

CodeBuddy：工程沙箱、命令确认、改动可回滚（代码天生可回滚，这是它的优势）

 

Docker 那份沙箱规范（我们 10 月 4 日讲过）：把“能做什么”做成可版本化、可审查的标准

这一层是 dots 这次投入最重的地方之一，也是最容易被用户忽略的地方。

没有 Harness，再聪明的 Agent 也可能闯祸 —— 第 7 期那句话，现在读起来更实在了。

第 6 层 MCP：拼生态宽度

 

dots：4000+ 应用、插件可内嵌编辑器与仪表盘、Agents API 支持 Computer Use

 

CodeBuddy：MCP 工具 + 终端 + 仓库，宽度不如 dots，但深度在“工程现场”

 

豆包：字节的内容与服务生态

宽度决定它能碰到多少东西，深度决定它在某一个地方能不能干到底。

第 7 层 Skills：拼“开箱能用多少”

技能库这块，各家都在堆。dots 有生态里的现成能力，CodeBuddy 有代码相关的一整套（重构、测试、审查），豆包和 WorkBuddy 偏办公与内容。

判断标准很简单：装上第一天，它能替你干成几件真事。

七层对照


03

MAP

三、所以，各自在哪一层用力

把上面收敛成一句：

 

dots：重心在 第 4 层（常驻 Agent）+ 第 5 层（Harness）+ 第 6 层（生态宽度）。它卖的不是“更聪明”，而是 一直在岗、有身份、有边界、能碰到你所有的工具。

 

豆包：重心在 第 3 层（上下文/中文语境）+ 第 7 层（技能丰富度）。它是你最容易叫得动的那一个。

 

CodeBuddy：重心在 第 6、7 层（工程工具链与代码技能）+ 第 5 层（沙箱与可回滚）。在“改代码”这件事上，它比通用 Agent 深得多。

 

WorkBuddy：重心在 第 4 层 + 第 7 层，把办公任务做成可交付的结果。

一句话总结：dots 做的是“关系”（常驻、身份、权限），豆包做的是“顺手”（叫得动、懂中文），CodeBuddy 做的是“深度”（工程现场），WorkBuddy 做的是“交付”（办公成品）。


04

LINK

四、它们之间的联系

别把它们看成四个互相替换的东西，其实是同一套结构的不同切面：

 

底下的 Token、提示词、上下文，四家共用同一套技术底座

 

中间的 Agent 与 Harness，是最近两年真正的竞争焦点

 

上面的 MCP 与 Skills，决定谁能先把“能干成的事”铺满

所以你会看到 dots 一发布，大家马上拿它跟“小龙虾”那一脉比；也会看到 CodeBuddy 这类工具把 Harness 和 Skills 越做越重。不是谁抄谁，是整条链子在同时往上长。


05

YOU

五、普通人怎么选

三条建议：

一、按“在哪一层需要它”选，不按名气选。 写代码找 CodeBuddy 这类工程工具；日常随口问找豆包；要把一整段流程长期交给它，再看 dots 这类常驻型。

二、常驻型的东西，先从小权限开始。 它在岗时间越长，持权越久。先给它最小权限，跑顺了再放开。

三、看日志，不看宣传。 它干过什么你能不能查到，这是硬指标。查不到，就别给它钱和隐私相关的活。

THE END

最后

这一周我们看了很多新东西：更便宜的模型、更长的在岗时间、更多的权限配置。

但如果只记一句，我建议是这句：

模型能力会越来越接近，真正拉开差距的是它在哪一层用力，以及你给它划了多大的圈。

下次有人跟你说“某某 AI 又碾压了谁”，你可以先问一句：它是在哪一层赢的？那一层，我用得上吗？

明天（10 月 6 日）讲多智能体编排：一个 AI 干不完，就来一群 —— 也包括 dots 以后多个组队这件事。
