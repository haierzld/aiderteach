普通人也能做出“真产品”

把两次“AI 造物”经历摆在一起复盘，提炼成一条可复制的五步流水线

两期实操 · 一条流水线 · 一份可抄清单

AI 造物 全流程复盘

大家好，我是小智。前两期，我分别用 CodeBuddy 做了一个开源到 GitHub 的 Markdown 打印插件、一套成功提交到微信表情开放平台的表情包。做完之后收到不少读者留言：这两件事看起来八竿子打不着，到底是怎么一步步做出来的？普通人照着来，真能复刻吗？今天这篇，我把两次“从想法到上线/上架”的经历摆在一起，从头复盘，提炼成一条可以复制的五步流水线。

先说结论： 造一个“真产品”的门槛，从来没有像现在这么低过 。但门槛越低的地方，越容易在你想不到的位置翻车。

📌 本文看点

 

一条“AI 造物”五步流水线：从想法到上线，每一步具体干什么

 

两个案例对照复盘：做“软件”和做“表情包”，套路竟然一模一样

 

最容易翻车的三个地方，和我的“验收员”心法

 

文末附一张可以直接抄的《普通人开工清单》

 
01

先对齐：什么才算“真产品”

普通人的三条标准：小、真、能交付

开始之前，先把“真产品”说清楚——我不是让你去做下一个微信。我的标准只有三条：

1

小：解决你自己或身边人一个具体的小问题，不做“大而全”；

2

真：真能跑起来、真能上架，而不是一个只能看不能用的“概念演示”；

3

能交付：别人能用上——装进编辑器、从商店下载，或者直接在开源仓库里看到。

拿前两期的例子说：

Markdown 打印插件，源于我自己一个痛点：文档写好了想打印成 PDF，编辑器里却总差一个“顺手的打印键”。小到不能再小，但它解决了真实问题，最后装进编辑器就能用，还能开源给别人用。

微信表情包，源于一个朴素的心愿：给家里爱发表情的长辈做一套“专属款”，最好还带点家乡味道。它不算“软件”，但同样是一个能被别人下载、使用的完整产品。

你会发现，这两个东西一个偏“技术”、一个偏“创意”，但它们走完的流程几乎一样。这恰恰是今天最想告诉你的： “AI 造物”的套路是通用的，跟你会不会写代码、是不是设计师没关系 。

02

五步流水线：两次实践提炼出的通用路径

说清需求 → 做最小版 → 让 AI 干活 → 自己验收 → 补齐交付物

把两次经历拆开揉碎，它们都走了同一条路，五步。下面一步一步拆。

03

第一步：把想法“说成人话”

目标、约束、验收标准，三样说清楚

给 AI 的第一句话，永远不要是“帮我做个插件”“帮我画套表情”这种空指令。我给它的是三样东西：

1

目标：这东西最终解决什么问题、在什么环境里用；

2

约束：有哪些红线不能碰（依赖、平台、风格要求）；

3

验收标准：做到什么程度算“成了”。

打印插件那次，我给的原始需求是：

目标：做一个 VS Code / CodeBuddy 的打印扩展；约束：零第三方依赖，装上就能用；验收标准：Markdown 按排版渲染，能打包成 .vsix，右键菜单、状态栏、快捷键三个入口都要有。

表情包那次更典型——我没直接喊“画 8 张表情”，而是先花十分钟写了一张“角色卡”：

8~10 岁圆脸小女孩，大眼、红润脸颊；头顶白色茉莉花环（福州市花）；粉色中式汉服小褂、双丸髻系粉色丝带；性格温柔治愈，口头禅“妈妈的专属小可爱”。

后面每一次绘图指令，我都把这段原样带上。

心法：AI 不缺能力，缺的是“你想要的到底是什么”的边界。需求说得越清楚，后面返工越少——这一步值得花十分钟，它是整条流水线里性价比最高的一步。

04

第二步：先做“能跑的 1.0”

最小版不是偷工减料，是快速验证方向

很多人一上来就想要完整版：插件要支持十种格式，表情一上来就要 16 张。我的做法相反——先做最小版：

 

插件：先跑通“把一份 Markdown 渲染成好看的样子并能打印”这个最小闭环，确认方向没错，再去补各种入口和边界情况；

 

表情包：先只出 1~2 张，看角色风格是不是统一、是不是我想要的感觉，统一了再批量生成整套 8 张。

最小版不是偷工减料，是花最小成本验证方向。方向错了，做一半才发现不对，浪费的可不是一小时——是让 AI 反复返工的一整天。

05

第三步：让 AI 干活，但“一次只喂一步”

拆得越小，验收越频繁，翻车成本越低

这是最容易理解错的一步。AI 明明能一次干很多，为什么非要一次只喂一步？ 因为任务越大，它“自作主张”的空间就越大 。两个项目里我的做法都是：

 

插件：先让它读相关文件、理清结构，再写渲染核心，再写编辑器入口，分阶段推进。每次改代码前，先确认它真的“看”过文件，而不是凭记忆硬写；

 

表情包：每一轮只给它“角色卡 + 一个动作描述”，一次生成一两张，不满意当场改，而不是一口气批量 16 张然后集体返工。

把大任务拆成 AI 一次能做好、你能一眼看明白的小任务。你验收得越频繁，翻车成本越低。

06

第四步：自己当“验收员”——AI 会自作聪明

整条流水线里最贵的一课，单独拿出来讲

打印插件上线后修一个 Bug 时，AI 给了个“聪明”方案：缓存“上一次打开的文件”，拿不到当前文件就用缓存兜底。听起来无懈可击，其实埋了个雷：当用户打开新文档 B 去打印，一旦上下文解析失败，系统会把上一份文档 A 打印出来。 打印错文件，比打印不出来更可怕 ——纸已经出来了，错就造成了。

!

“兜底方案”往往是雷

最后改成“当前上下文逐级精确”：光标所在文件 → 当前激活标签页 → 从预览标题反查源文件……实在有多个候选，就弹出列表让用户自己点选，绝不偷偷用“历史文件”。

表情包那边也有类似教训：AI 生成的 GIF 动不动超 500KB，它会自作主张“偷偷抽帧降画质”——动起来一顿一顿的，比文件大一点更难看。最后是我盯着每一帧的流畅度验收，才找到“又小又顺”的压缩档位。

凡是 AI 拿不准的，宁可停下来让用户确认，也不要自作主张去猜。你才是那个要对结果负责的“验收员”，AI 只是手快。

07

第五步：发布/上架——“交付物齐全”才算成品

从“作品”到“产品”，就差这最后一道门槛

做完主体，很多人以为就结束了。其实发布才是新手最容易卡住的地方，因为 AI 只帮你做出“作品”，平台要的“材料全家桶”得你自己盯：

 

软件类：除了功能，还要 README、截图、License、Release 版本、可安装的 .vsix 包，一个都不能少才能体面地开源；

 

表情包类：主页横幅、头像、主图和封面、赞赏图、动图尺寸规范、创作说明……提交审核时缺一样就给你打回来。

开工前就把“发布清单”列好，别等作品做完了才发现还差一堆材料。这一步是“从作品到产品”的最后一道门槛，也是拉开差距的地方。

08

两个产品，同一套套路

并排看，答案自己会说话

把两次经历并排看，会更直观：

环节 Markdown 打印插件 微信表情包
想法来源 自己打印文档的痛点 想给长辈做专属表情
给 AI 的第一份材料 目标/约束/验收标准三句话 一张“角色卡”
最小版 先跑通一份文档的渲染打印 先出 1~2 张定风格
最大的坑 AI“缓存历史文件”自作聪明 GIF 压缩偷帧掉画质
发布门槛 README/License/.vsix 齐全 横幅/封面/审核材料齐全
共通教训 需求说清 → 小步快跑 → 盯紧验收 → 清单化交付

表格填完你会发现：不管是“代码产品”还是“内容产品”，底层是同一套流程。 你已经会的那件事——做 PPT、剪视频、写文档——套上这套流程，同样能变成“真产品” 。

09

普通人最容易翻车的三个地方

每条都配了对策，照着避坑

复盘完两次完整流程，我把最容易翻车的点收敛成三个：

1

一上来就想干票大的。对策：砍到“最小版”——先做一个“只记今天花了多少”的小工具，都是胜利。

2

没跟 AI 约定“拿不准怎么办”。对策：开工第一句就说清楚——“任何你不确定的地方，列出选项问我，不要自己决定。”

3

只管“做出来”，不管“交得齐”。对策：把发布清单放在开工清单里，一开始就规划。

!

别忘了合规底线

形象是自己定义的，就写原创；用了真实花朵、地名等元素，说明里写清创作依据；开源代码务必选好 License。别让“AI 造物”变成侵权翻车现场。

10

附：普通人开工清单（可直接抄）

整篇浓缩成一张清单，照着打勾

最后把整篇浓缩成一张清单，下次你想造点东西，照着打勾就行。

▍开工前 10 分钟（写下来再动手）

 

一句话目标：我想解决什么问题？

 

三条约束：平台/风格/红线是什么？

 

验收标准：做到什么程度算“成了”？

 

最小版范围：第一版只做哪一小块？

▍给 AI 的开场白模板

我要做一个【产品类型】，解决【问题】。约束是【约束】。请你先不要急着写，先问我不清楚的地方，然后给一个“最小版”的实施步骤。

▍发布前检查清单

 

软件类：README / 截图 / License / Release 包

 

内容类：封面 / 横幅 / 尺寸规范 / 创作说明

 

合规自查：原创声明 / 素材来源 / 授权

 

自己完整跑一遍“用户视角”的流程

▍顺手把“七层”挂上清单

上面是“怎么用”，下面是每步对应的“地基课”——都来自咱们已发的 AI 七层系列

 

开工前把想法“说成人话”——对应 第9期·提示词：AI 只按你给的边界作答，问得清，才做得对。

 

让 AI 先读文件、把角色卡带进每一轮——对应 第10期·上下文：它能“记得”什么，取决于你喂进去什么。

 

拆最小版、一次只喂一步——对应 第11期·Agent：AI 是会自己干活的 Agent，但活儿怎么拆，得你来。

 

在工作台里落地、接上工具插件——对应 第12期·Harness / 第13期·MCP / 第14期·Skills：AI 的“紧箍咒”“联络中枢”和“工具箱”。

 

自己当“验收员”、堵住自作聪明——对应 第8期·Token：想懂它为啥拿“缓存历史文件”兜底，先懂它其实是在逐字“猜”下一个词——边界只能你来守。

“用”和“懂”正好闭环：清单让你今晚就能开工，七层让你明天不再踩同一个坑。

第一次听说“七层”？先回看第7期总览一张图，再按需翻第8到14期（每期约10分钟），第15到17期三篇实战复盘是它的“全程演示版”。

11

小智说两句

难的从来不是技术，是开始的那一步

两期实操、一篇复盘，到这里，“用 AI 造一个真产品”这件事，我已经把我踩过的坑全交代完了。回想这两次经历，最深的感受是： AI 把“做出来”的成本压到了几乎为零，剩下的成本全在“想清楚”和“把住关” 。

从 0 到上线，从来没有像今天这么近——难的从来不是技术，是“先定一个小目标、然后开始”的那一步。而这一步，现在真的可以只花一个晚上。

—— 小智
